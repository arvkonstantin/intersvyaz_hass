# Домофон Интерсвязь для Home Assistant

![HACS Badge](https://img.shields.io/badge/HACS-Custom-orange.svg?style=flat-square)

![Домофон Интерсвязь](https://github.com/user-attachments/assets/0be9d430-7642-4955-8f43-d44bd06aa38b)

Интеграция Home Assistant для работы с домофонами **Интерсвязь**.

> Объединены кнопки всех дверей из форка @arvkonstantin и FCM из [форка @Lordhmen](https://github.com/Lordhmen/intersvyaz_hass).

> Это форк интеграции [hoolea/intersvyaz_hass](https://github.com/hoolea/intersvyaz_hass) от **@hoolea**. В форке добавлены уведомления о звонках в домофон через FCM-пуши.

## Возможности

- Просмотр камер подъездов
- Открытие двери прямо из Home Assistant
- Отдельные кнопки для всех доступных дверей и калиток каждого адреса
- Авторизация по номеру телефона
- Авторизация по логину и паролю
- Поддержка нескольких адресов
- Поток через **go2rtc (MSE)** с минимальной задержкой
- **Уведомления о звонках в домофон** в Home Assistant (push от Интерсвязи, без телефона и облачных посредников) — см. [раздел ниже](#5-уведомления-о-звонках-в-домофон)

# Установка

## Через HACS (рекомендуется)

[![Open your Home Assistant instance and open a repository inside the Home Assistant Community Store.](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=arvkonstantin&repository=intersvyaz_hass&category=integration)

Кнопка откроет HACS и предложит добавить этот репозиторий как пользовательский. Если кнопка не сработала, добавьте его вручную:

1. **HACS → ⋮ (меню в правом верхнем углу) → Пользовательские репозитории**.
2. В поле **Репозиторий** укажите `https://github.com/arvkonstantin/intersvyaz_hass`, в поле **Тип** выберите **Интеграция** и нажмите **Добавить**.
3. Найдите в HACS **Интерсвязь домофон** и установите.

> Если у вас уже установлена оригинальная интеграция от @hoolea, сначала удалите её из HACS, затем добавьте этот репозиторий.

После установки перезапустите Home Assistant.

## Ручная установка

1. Скачайте содержимое репозитория.
2. Скопируйте папку

```
custom_components/intersvyaz
```

в каталог

```
config/custom_components/
```

3. Перезапустите Home Assistant.

## 3. Настройте go2rtc

После авторизации интеграция автоматически отправляет конфигурацию потоков в **go2rtc** через HTTP API.

При необходимости можно изменить адрес сервера go2rtc в параметрах интеграции (**Интервал обновления**).

По умолчанию используется:

```
http://127.0.0.1:1984
```

После успешной настройки будут созданы:

- все камеры подъездов;
- отдельные кнопки **«Открыть: Главный вход»**, **«Открыть: Запасной вход»**,
  **«Открыть: Калитка …»** для всех доступных реле каждого адреса;
- прежняя кнопка **«Открыть»** для совместимости существующих автоматизаций.

### Кнопки всех домофонов

Для каждого адреса интеграция получает весь список `GET /domofon/relays`.
Название берётся из описания двери (`RELAY_DESCR`), типа (`RELAY_TYPE`),
адреса (`ADDRESS`), либо ID, если описания нет. Каждая отдельная кнопка
привязана к своему `RELAY_ID`; её идентификатор не зависит от порядка списка
и названия двери. Несколько адресов с одинаковым `RELAY_ID` не смешиваются.

Новые двери обнаруживаются автоматически с настроенным интервалом обновления:
один запрос списка на адрес, независимо от количества кнопок. Исчезнувшая дверь
становится недоступной; если вернётся, восстановится прежняя сущность.
Перед открытием отдельная кнопка обновляет список и подтверждает наличие именно
выбранной двери. При ошибке запроса / открытия она не выбирает первую дверь
и не повторяет потенциально уже выполненную команду.

Существующая кнопка **«Открыть»** и действие **`intersvyaz.open_door`** сохраняют
прежние идентификаторы и поведение — открытие первого домофона адреса.
Они оставлены для совместимости; для явного выбора используйте новые кнопки.
Например, при пяти реле появятся пять отдельных кнопок и одна прежняя.
Прежнюю кнопку при необходимости можно отключить в реестре сущностей.

Ошибка загрузки списка дверей не блокирует камеры и прежнюю кнопку;
обнаружение повторяется при следующем обновлении. Подписанные ссылки снимков
и секреты QR не публикуются в атрибутах кнопок.

## 5. Уведомления о звонках в домофон

Когда кто-то звонит в домофон, Интерсвязь отправляет push-уведомление в своё приложение через Firebase Cloud Messaging (FCM). Интеграция умеет регистрировать Home Assistant как ещё одно «устройство» вашего аккаунта и получать эти же пуши напрямую — без телефона, без официального приложения и без сторонних серверов.

### Что это даёт

При звонке в домофон в Home Assistant:

- сенсор **«Звонок»** (`sensor.<адрес>_zvonok`) на 5 секунд переходит в состояние `Звонок`, затем сам возвращается в `Нет`;
- генерируется событие **`intersvyaz_incoming_call`** (в данных события: `source: fcm` и `message_id`).

### Требования

- Известный интеграции **номер телефона**, на который зарегистрирован аккаунт Интерсвязи:
  - при входе **по номеру телефона** он уже есть;
  - при входе **по логину и паролю** его нужно указать вручную (см. ниже) — сервер Интерсвязи в этом случае номер не отдаёт.
- Исходящее соединение с `mtalk.google.com:5228` (постоянное TLS-соединение с Google FCM). Если трафик идёт через VPN/прокси, убедитесь, что это соединение не рвётся.

### Как включить

1. **Настройки → Устройства и службы → Домофон Интерсвязь → Настроить → Интервал обновления**.
2. Если интеграция настроена по логину и паролю и номер ещё не указан — заполните поле **«Номер телефона (для push-уведомлений о звонках)»** в формате `+7XXXXXXXXXX` и сохраните. Затем снова откройте этот же экран.
3. Включите **«Включить FCM-слушатель звонков»** и сохраните. Интеграция перезагрузится.

После включения в личном кабинете Интерсвязи появится дополнительное устройство **«Home Assistant»**. Оно получает пуши о звонках так же, как телефон с приложением; на ваш телефон уведомления продолжат приходить как раньше.

### Как проверить

Сразу после включения появятся диагностические сенсоры:

| Сенсор | Что показывает |
|---|---|
| `sensor.intersvyaz_fcm_status_<id>` | Состояние слушателя: `слушает`, `плановое переподключение`, ошибки подключения/регистрации |
| `sensor.intersvyaz_last_push_<id>` | Последний полученный пуш и его содержимое в атрибутах |
| `sensor.intersvyaz_device_settings_<id>` | Как сервер Интерсвязи видит зарегистрированное устройство |

Если статус `слушает` — позвоните в домофон: сенсор «Звонок» должен сработать в течение секунды.

Если не сработал — включите отладочный лог для интеграции (**Настройки → Устройства и службы → Домофон Интерсвязь → ⋮ → Включить отладочное журналирование**), повторите звонок и посмотрите строки `custom_components.intersvyaz.fcm_listener` и `fcm_patch` в журнале.

### Ограничения

- Пуш о звонке распознаётся по признаку «пуш без поля `data`». Обычные уведомления Интерсвязи (новости, баланс и т.п.) содержат `data` и звонком не считаются, но редкие ложные срабатывания не исключены.
- Соединение с FCM раз в 15 минут планово переподключается — это страховка от «тихого» обрыва соединения на стороне Google.
- Функция основана на разборе протокола официального приложения и может перестать работать, если Интерсвязь изменит формат пушей.

## Объединённый релиз 1.4.0

Кнопки всех реле из ветки `feat/all-intercom-buttons` @arvkonstantin и FCM-подписка @Lordhmen сохранены в одном источнике установки HACS. Прежние camera/button unique_id сохранены. Переключение форка не требует повторного SMS-входа.

Для Frigate используйте go2rtc, встроенный в Frigate: включите опцию интеграции и укажите URL его API. Имя потока постоянно: `intersvyaz_<UUID камеры с подчёркиваниями вместо дефисов>`. Оно также доступно в атрибуте камеры `go2rtc_stream`. Источник с подписанной ссылкой обновляется при каждом обновлении координатора. Открытие должно направляться на отдельную кнопку с конкретным `relay_id`, не на старый общий action `intersvyaz.open_door`.

Важно: пустой FCM-push означает **предполагаемый**, а не достоверно подтверждённый звонок. В событии теперь есть `entry_id`, `assumed_call: true`, `received_at` и ID сообщения из callback. Такой push не должен запускать открытие двери. Повреждённое сообщение / ошибка расшифровки не создаёт событие звонка. Содержимое необработанных push и ключи устройства не публикуются в state / логах. Имена и signed URL потоков в штатных логах скрыты.

Исправление base64 реализовано собственным subclass `IntersvyazFcmPushClient`: исходники и класс общей `firebase-messaging` не патчатся. Версия зависимости закреплена. Память FCM защищена от параллельных записей, background task корректно завершается при выгрузке.
